# 安卓 FlClash：原始远程订阅 + 覆写脚本

已验证版本：FlClash 0.8.98，小米 14。先核对实际版本和界面。用户选择指导模式时，给出单步路径和观察点，由用户操作；USB 已连接不代表可以恢复自动接管。

## 先检查已有覆写

保留原始远程订阅，优先复用客户端已有的住宅代理脚本。先读脚本逻辑，再判断适用范围：名称或注释写着「良心云」不等于代码只能用于良心云。

本次已有脚本「美国链式1024proxy」的有效逻辑：

1. 从当前订阅的 `config.proxies` 筛选名称含「美国」的节点，排除住宅出口自身；没有匹配时取前 8 个机场节点兜底。
2. 创建「链式入口」`url-test` 分组，最多 10 个入口，`interval: 300`、`tolerance: 50`。
3. 追加 SOCKS5 节点「美国静态出口」，其 `dialer-proxy` 指向「链式入口」。真实地址和账密保留在客户端。
4. 将住宅出口插入含「自动选择」成员的主分组。每次应用订阅时根据当前节点重建入口，不固定机场节点名。

复用同一脚本的条件是：订阅提供 `config.proxies`，且目标主分组满足脚本的匹配条件。只含 `proxy-providers` 的配置需要单独处理，不能假设扫描 `config.proxies` 能取到它的节点。

新增或调整插入逻辑时，限制到手动选择组并防止重复，例如：

```js
for (const g of config["proxy-groups"] || []) {
  if (g.type === "select" && Array.isArray(g.proxies)
      && g.proxies.includes("自动选择") && !g.proxies.includes(EXIT)) {
    g.proxies.unshift(EXIT);
  }
}
```

`EXIT` 为住宅出口名。入口池不能包含该出口或依赖它的链式节点，避免递归套链。若主分组没有「自动选择」成员，应按实际分组结构调整匹配，不能只因脚本已保存就判定可用。

## 给每个订阅关联脚本

1. 配置页 → **原始远程订阅**右侧 `⋮` → 更多 → 覆写。
2. 覆写模式选择「脚本」，再勾选具体脚本，让其单选圆点变为实心。只在脚本管理页创建或保存脚本不会自动关联订阅。
3. 对其他订阅分别重复关联；多个订阅可以引用同一份脚本。
4. 切换到该订阅，在代理页的主分组中选择住宅出口。本次对应关系：

| 订阅 | 主分组 | 应选出口 |
|---|---|---|
| 新良心云 | 良心云 | 美国静态出口 |
| 魔戒.net | 节点选择 | 美国静态出口 |
| 赛博云 | 赛博云 | 美国静态出口 |

「链式入口」保持自动选择美国节点。订阅仍按原远程地址更新，脚本关联独立保存；正常更新不会主动清除关联，升级客户端后复查。重新导入的订阅是新记录，需要重新勾选脚本。

## 验证与排错

逐个切换订阅、启动 FlClash，用**手机浏览器**访问 [api.ipify.org](https://api.ipify.org)。结果与客户端配置中的住宅出口 IP 一致，才能确认该订阅的这条链路生效。入口出现美国节点、延迟测试通过或电脑端同配置测试通过，都不能替代手机出口验证。

- **只有 `COMPATIBLE`**：入口组没有实际可用成员。核对脚本关联、原订阅是否加载节点、美国节点匹配和入口成员；不能把它当作住宅节点。
- **看到机场 IP**：先检查规则命中的主分组是否选了住宅出口，再检查出口的 `dialer-proxy`。
- **订阅更新 403**：这是订阅下载问题；核对订阅地址与更新路径。重新导入可用地址后，给新记录关联脚本，不能把配置链式出口当成修复了订阅下载。
- **个别应用出口不同**：检查该应用的规则和独立分组。魔戒的 TikTok 等分组不一定经过主分组，也不一定含「自动选择」；主分组验证通过不代表全部分流都已套链。

默认沿用已验证的远程订阅加本地覆写。已有覆写能满足任务时，无需另外生成整份本地 YAML 和嵌套远程 provider。确需独立文件时，另外验证首次订阅下载失败时的入口可用性；本次无初始节点的文件方案曾只显示 `COMPATIBLE`。

## 本次验证记录（2026-11-10）

- 用户在手机上复用已有脚本，为魔戒、新良心云、赛博云分别关联并选中「美国静态出口」。
- 用户先确认魔戒入口出现美国节点、手机浏览器出口与住宅出口一致，随后确认另外两个订阅也有效。
- 结论来自用户在手机上的实际反馈，不是 ADB 或电脑代理测试。住宅 IP、账密及完整订阅链接不记录到仓库。
