# 独立评审、交叉质询与固定量表

## 1. 不可降低的评审协议

每个角色由不同评审身份承担；评审者不得参与被审版本修改，同一身份在本阶段只担任一个角色。每轮按以下顺序执行：

1. 只向每席提供原始赛题/数据、当年官方规则、同一候选版本、本 Skill 和自己的量表；
2. 不提供目标分数、已知缺陷、前轮结论、修订说明或其他评委意见；
3. 每席独立核验并写出报告、分数和证据位置；
4. 全部报告完成后才进行交叉质询，集中检查结论冲突、遗漏和伪独立证据；
5. 质询发现的新问题按致命/主要/次要记录；任何未解决问题都阻塞；
6. 作者修改后候选版本变化，原分数全部失效，由未参与修改的新评委盲评。

交叉质询不能用于互相说服加分；原始独立分数不得上调。需要题型专项知识时增加 `ADDITIONAL-*` 专家，不得删除、合并或让一人兼任必需角色。无法建立真实独立性时标为“非独立预审”，正式状态 `BLOCKED`。

## 2. 评分与严重性

每席五项，每项 20 分，总分 100；单项只能取：

| 分数 | 判定 |
|---:|---|
| 20 | 证据完整、可执行、无实质缺陷 |
| 15 | 有次要缺口，不改变主要结论 |
| 10 | 主要证据不完整，需要较大修订 |
| 5 | 严重错误、不可执行或大范围缺失 |
| 0 | 缺失、与事实冲突、伪造或触发否决 |

- **致命问题**：正确性、硬约束、真实性、复现、官方合规或独立性失败；直接 `BLOCKED`。
- **主要问题**：可能改变模型、结果、结论或评委判断；必须修订。
- **次要问题**：不改变结论但降低清晰度或审计效率；满分前也必须关闭。

满分必须五项均 20、无否决项、无发现、无缺失证据。每个 20 都必须引用具体文件/页/产物 ID/命令证据；五项合计至少覆盖三个产物，并包含本角色的专项产物锚点。不能用主观认可、降低标准、删除角色或把脚本 PASS 当语义证据。阶段一涉及官方语义、单位或小问全集时，必须同时核对官方材料校验文件，确认赛题和数据未被改动。

## 3. 阶段一八席

在阶段一先用以下八个角色执行[多路方案盲评选优](stage1-proposal-tournament.md)，并按题型专项风险动态增加 `ADDITIONAL-*`。每席对全部候选分别应用自己的五项标准；每个候选的比较分可以低于满分，全部选优评委合计最高且无否决项者获胜。该比较分只用于选择主路线，不授予阶段 `PASS`，也不充当终审。胜者完善为最终模型合同后，另由未参与方案编写、选优或修改的全新终审团按本文件第 1–2 节执行正式评审；八个既有角色为最低配置，仍可动态增席。

### `S1-JUDGE` 国赛评委

1. 所有官方小问、结果文件和评分入口闭合；
2. 核心机制、逐问答案路径和亮点可发现；
3. 模型复杂度与题目价值匹配；
4. 验证方向足以建立评委可信度；
5. 限制、阻塞和可提交边界诚实。

### `S1-DOMAIN` 领域专家

1. 对象、状态和机制符合领域规律；
2. 外部参数、定律和事实来源权威可追溯；
3. 假设的偏差方向、适用范围和失效场景正确；
4. 边界/初值、尺度和现实约束完整；
5. 建议与领域证据边界一致。

### `S1-PROBLEM` 审题专家

1. 题面事实、推断、假设和外部事实严格分开；
2. 对象、目标、指标、单位、精度和交付物逐问闭合；
3. 小问递进/分层/并列关系和口径转换正确；
4. 无漏问、偷换对象、时间窗、分母或场景；
5. 任务矩阵与官方题面逐项可追溯。

### `S1-RIGOR` 数学严谨性专家

1. 变量类型、定义域、单位、方程、目标和约束明确；
2. 边界/初值、量纲、尺度、退化和极限检查完整；
3. 可行域、容差、约束冲突和可行见证可审计；
4. 数学结构可识别、可计算且表述无歧义；
5. 算法与数学结构、求解状态和误差要求一致。

### `S1-INNOVATION` 模型创新专家

1. 创新直接对应当前题目痛点；
2. 与基础模型、既有方法或历史实例的差分具体；
3. 创新来自机制/状态/约束/指标/接口而非名称；
4. 增益、代价、风险和消融/对照计划完整；
5. 无历史结论迁移、技术堆叠或无证据自评。

### `S1-IDENTIFIABILITY` 可辨识性与假设专家

1. 结构/实践可辨识性、共线或病态风险已检查；
2. 有效样本、参数自由度、类别/时间/场景覆盖充分；
3. 缺失、删失、测量误差、标签和代表性已处理；
4. 假设有依据、偏差、范围、失效和修正；
5. 外推范围、不可识别参数和数据不足被阻塞。

### `S1-SIMPLE` Simple-yet-efficient 专家

1. 先有可独立运行的解析/精确/简化基线；
2. 每个模块有不可替代接口，冗余已删除；
3. 改进由明确失效证据触发；
4. 实例规模、复杂度、时间/内存、环境和许可可行；
5. 参数、初始化、停止、随机预算和失败状态可执行。

### `S1-REDTEAM` 对抗性反例专家

1. 漏问、口径、单位和时间尺度反例已覆盖；
2. 硬约束冲突、空可行域和极端边界已覆盖；
3. 不可识别、数据不足、因果越界和历史迁移已覆盖；
4. 验证共享错误源、阈值后设和伪独立风险已覆盖；
5. 风险表含触发、检测、影响、处置和关闭证据。

## 4. 阶段二八席

### `S2-NUMERICAL` 数值算法专家

1. 代码忠实实现方程、变量和约束；
2. 精度、容差、离散、收敛和数值稳定有证据；
3. 状态、bound、gap、不可行/无界结论正确；
4. 基线、极限、守恒和独立数值对照通过；
5. 全部硬约束证书和合理精度通过。

### `S2-ENGINEERING` 软件工程专家

1. 原始输入只读，错误和退出状态不伪成功；
2. 模块、配置、路径和接口清楚；
3. 运行入口可移植，日志和异常处理真实；
4. 文件、字段和生产命令完整；
5. 支撑包包含实际使用的全部代码与资源。

### `S2-EXPERIMENT` 实验设计与统计专家

1. 基线、对照、消融与改进问题对应；
2. 指标、样本单位、重复次数和功效合理；
3. 区间、效应量、误差和多重比较按任务正确；
4. 现实参数敏感性、联合扰动和切换边界完整；
5. 失败实验、负结果和结论边界如实报告。

### `S2-DATA` 数据质量专家

1. 字段、单位、外键、重复、缺失和异常已审计；
2. 独立单位、事件和记录口径正确；
3. 切分/不切分设计符合分析模式；
4. 预处理、调参、后验特征和测试集无泄漏；
5. 标签、代表性、删失和外推风险有证据。

### `S2-PERFORMANCE` 性能复杂度专家

1. 理论复杂度与真实实例规模一致；
2. 时间、内存、线程和硬件记录完整；
3. 性能基准、瓶颈和规模退化已测试；
4. 超时/中断有降级、回退或阻塞策略；
5. 性能优化不改变数学问题或牺牲正确性。

### `S2-REPRODUCIBILITY` 复现性专家

1. 环境、依赖、求解器和版本锁定；
2. 命令、配置、种子和非确定性完整；
3. 干净环境可重建核心数字、表、图和结果文件；
4. 输入、产物、配置和日志一致，核心结果可按登记哈希复算；
5. 复现失败不会被包装为成功。

### `S2-VISUALIZATION` 科学可视化专家

1. 每图有明确证据任务和正确数据源；
2. 轴、单位、图例、色条、误差和场景完整；
3. 视觉编码、比例、颜色和二维/三维选择诚实；
4. 绘图数据、代码和配置可复现；
5. 图后结论不过界且与数字台账一致。

### `S2-MODEL-CODE` 模型—代码一致性审计员

1. 模型/变量/约束 ID 与代码位置一一对应；
2. 参数、初值、停止和状态解释一致；
3. 代码输出字段与结果、图表、论文主张一致；
4. 无未执行分支、隐藏人工改数或孤立脚本；
5. 模型变化已回退阶段一并使旧结果失效。

## 5. 阶段三八席

### `S3-JUDGE` 国赛终审评委

1. 标题摘要能快速确认全部小问完成；
2. 核心机制、答案、验证和创新易发现；
3. 正文信息密度和评委阅读路径合理；
4. 规定结果文件和建议可直接执行；
5. 无会降低奖项判断的事实或呈现缺陷。

### `S3-ARGUMENT` 学术论证专家

1. 模型—算法—结果—检验逐问相邻；
2. 公式动机、编号、符号、单位和回引完整；
3. 假设、推导、证据和结论逻辑闭合；
4. 强度、因果、最优性和鲁棒性措辞不过界；
5. 局限、失效和替代解释诚实。

### `S3-ABSTRACT` 摘要专家

1. 每问都有任务和核心方法；
2. 每问都有与 `answer_kind` 相符的关键答案；数值型给单位和合理精度，其他类型不强造单位；
3. 每问都有验证证据或可信度边界；
4. 规定结果文件、创新和限制可发现；
5. 与正文、台账和官方长度/格式完全一致。

### `S3-VISUAL` 图表表达专家

1. 一图/一表服务一个主要论证任务；
2. 数据、轴、单位、图例、题注和正文解释完整；
3. 打印、黑白、字体、颜色和比例可读；
4. 无装饰性 3D、彩虹色、截图或误导编码；
5. 图表与生成代码、台账和正文结论一致。

### `S3-CONSISTENCY` 结果一致性审计员

1. 题面—任务矩阵无漏问和对象变化；
2. 模型—代码参数、约束和状态一致；
3. 摘要—正文—附录数字、单位和口径一致；
4. 图表—结果文件—规定附件逐字段一致；
5. PDF—可编辑源—支撑包来自同一版本。

### `S3-CITATION-COMPLIANCE` 引用与合规专家

1. 引用真实、权威且正文/文末一一对应；
2. 参数、定律、算法和外部数据均有适当来源；
3. 当年模板、命名、页数/大小和提交规则通过；
4. AI、软件、数据和外部资料按规则披露；
5. 无学术不端、越权搜索或历史答案迁移。

### `S3-TYPESETTING` 排版专家

1. 可编辑源可无错误重建最终 PDF；
2. 页面、公式、表格、图像、题注和页码无缺陷；
3. 字体、字号、留白、分页和层级打印可读；
4. PDF 非空、可打开、页数与源一致；
5. 附录代码和大表可读且没有破坏正文路径。

### `S3-ANON-REDTEAM` 匿名审稿红队

1. 正文、元数据、文件名和附件无身份泄露；
2. 无漏问、硬约束失败、虚假最优或因果越界；
3. 无编造数据、运行、图表、引用或评审；
4. 支撑包完整、可解压、可运行且无隐藏文件风险；
5. 任何证据/合规缺口都被阻塞而非包装。

## 6. 否决项

以下任一存在时相关席不得满分，正式状态 `BLOCKED`：

- 内部矛盾、漏问、硬约束失败或强制交付物缺失；
- 编造数据、参数、文献、运行、图表、评审身份或验证；
- 代码未运行却声称已运行，文件未渲染却声称格式通过；
- 数据泄漏、伪独立验证、挑选幸运种子或结果不可复现；
- 无证据宣称全局最优、不可行、无界、因果、鲁棒或普适；
- 违反官方模板、匿名、诚信、AI 披露或提交规则；
- 评审者参与修改、初始评分前看到他人结论或身份不独立；
- 交叉质询仍有未解决的致命、主要或次要问题。

## 7. 报告与交叉质询记录

每席报告是独立文件，写入阶段工作目录并在阶段清单登记，至少包含：

```markdown
角色：
评审者 ID：
被审候选版本：
五项分数：20/20/20/20/20
总分：
否决项：
致命问题：
主要问题：
次要问题：
正面证据位置：
缺失证据：
结论：PASS / REVISE / BLOCKED
独立性声明：
```

每项分数给出非空判定理由和 `相对路径#定位` 证据。全部八席报告完成后进行交叉质询，集中检查：分数冲突、事实冲突、共享错误源、角色覆盖空白、否决项和动态增席需求；任何未解决问题都阻塞。

## 8. 修订与重评

- 阶段一/二：实质修改后由该阶段全套新评委重评；
- 阶段三：论文或包修改后由阶段三八席全套新评委重评；
- 不向重评者提供旧缺陷、旧分数或修订目标；
- 材料、工具或独立身份不足时保持 `BLOCKED`，不得合并角色制造满分。
