# forge-cumcm-solution

> 一个面向 AI Agent 的 **CUMCM（全国大学生数学建模竞赛，国赛）全流程 Skill**：把「审题建模 → 代码求解与验证 → 论文写作与提交审查」三个阶段的全部质量要求，固化为一套按权威特征文件实现、评审团盲审、修订后再审的循环体系，驱动 Agent 端到端产出接近提交级的竞赛成果。

## 项目背景

国赛优秀论文的稳定特征不是「模型越多越好」，而是一条完整的证据链：

> **准确理解题目 → 建立统一机制 → 选择匹配算法 → 给出可执行结果 → 建立可信证据 → 用评委能快速验证的方式呈现。**

但让 AI Agent 独立完成这样的全流程，常见的失败模式是：堆砌算法名词、编造运行结果、数据泄漏、摘要与正文数字冲突、用截图制造完成感。本 Skill 通过**按指南特征高质量实现、八席并行盲审、主 agent 仲裁与满分门禁**等机制，把上述失败模式逐条变成评审中可发现、可阻塞的问题。

本项目以《国赛优秀数学建模论文特征与模仿指南-综合版》v1.0（基于 2023—2025 年 15 道国赛题目与 37 篇优秀论文的六轮专项分析）为唯一权威方法论来源。

## 核心特性

- **三阶段流水线**：阶段一审题与模型、阶段二求解与结果证据、阶段三论文与提交，逐级通过、逐级验收，前序不过不开工。
- **实现—评审—修订循环**：每阶段按权威指南特征实现，执行者自查冻结后由八席并行盲审；评审结果以文本返回主 agent，主 agent 仲裁汇总、形成修改清单转交执行线，修订后只复审受影响席位。
- **八席独立评审**：每阶段 8 个专业角色（可按题型风险动态增席），互相隔离、并行盲审；五项各 20 分、总分 100，全部 100/100 且无未关闭问题才通过。评审产物只走对话，不落盘。
- **数字一致性**：关键数字先入台账，论文表图只能引用台账数字；答案、代码输出、结果文件与论文数字可相互追溯。
- **落盘白名单**：工作目录只保留交付物本身（模型总结、代码与运行说明、结果文件、图表数据、论文与 PDF）；评审报告、状态文件、manifest、哈希/版本副本一律禁止。
- **诚实阻塞**：缺少会改变结论的题目、数据、规则、模板、运行环境或独立评审能力时，只能报告 `BLOCKED`，禁止虚构满分或包装未通过版本。

## 使用方式

本仓库是一个纯 Markdown 的 Skill 包，无运行时依赖。

**全流程作答**：将本 Skill 提供给支持 SKILL.md 规范的 Agent，给出赛题与附件即可。默认每个阶段通过八席满分评审后暂停确认；明确要求端到端运行时连续推进。

**阶段续作 / 已有论文审查**：Skill 内建路由——续作先核验前序成果；审查已有论文从阶段三开始，但模型或数字断链必须回退阶段一或二。

## 每阶段执行循环

1. **读材料与指南**——按主 Skill 给出的章节号只加载相关章节，不整份塞入上下文；
2. **实现**——把指南特征转成本题动作与验收条件，派执行线完成本阶段交付物；
3. **自查冻结**——执行者按八席量表逐席自查修正，冻结候选版本；
4. **八席盲审**——八个评审 agent 并行评审，文本返回分数、否决与问题清单；
5. **仲裁与修订**——主 agent 汇总去重、解决席位冲突，修改清单转交执行线，修订后只请受影响席复核；
6. **通过或继续**——八席全部 100/100、无否决、无未关闭问题才交付并暂停，否则继续循环。

## 绝对禁止

- 编造数据、参数来源、文献、运行结果、图表、评审身份或验证；
- 漏答小问、混用对象 / 场景 / 单位 / 分母，或让各处数字冲突；
- 把算法名当模型、把软件名当创新、为复杂而复杂；
- 无证明地声称全局最优、不可行、鲁棒、因果或普适；
- 用全数据预处理、特征选择或调参造成数据泄漏；
- 事后放宽约束容差、挑幸运随机种子或只报告最好一次；
- 用截图、装饰性 3D、彩虹色和空泛形容词制造完成感；
- 省略当年模板、匿名、文件命名、支撑材料或 AI 使用披露要求。

## 合规与诚信声明

- 「100 分」仅表示固定量表在当前证据范围内无未关闭问题，**不承诺任何奖项**。
- 本 Skill 用于提升建模与写作质量；使用者须遵守竞赛诚信要求，独立完成、如实披露 AI 使用情况。
